Loop Graph — component specs
Framework-agnostic specs for the read-only operations console. Tokens live in tokens.json; every component below renders from those values only. All components are pure functions of snapshot + SSE state — none dispatch writes.

1 · Layout & navigation model
Fixed 220px sidebar + scrolling content pane. Three top-level views; Loop detail is a drill-in from any run reference (Runs row, Failures card), never a nav item. Global banners stack above content: disconnected (red) always outranks needs_human (amber).

2 · Status badge system
One system everywhere a status appears: badge, row left-accent, timeline node, gate row, customer dot. Color is never alone — always glyph + verbatim lowercase enum label in mono. Tinted bg ≈10% alpha of fg, border ≈28%.
◔ running ✓ gate_passed ✕ gate_failed ⚑ needs_human ○ queued
aliases → engagement.new = queued · engagement.complete = passed · verdict.revise = running(↺) · verdict.escalate = needs_human · gate.pending = queued
needs_human additionally gets: 3px amber row accent + 4%-alpha row tint + global banner. It must be the loudest thing on any screen.
3 · Progress indicators — iteration n/4, attempt n/2
Iterations are segments (work accumulating toward a cap); attempts are dots (discrete retries — rare, so attempt>0 renders amber as a quiet warning). Always paired with a tabular mono fraction; never percentage bars.
2/4iteration — segment 14×4px r2, gap 3px, fill = status.fg, empty = border.default 1/2attempt — dot 6px, fill 0..n; amber when attempt>0 (a retry already happened)
4 · Iteration timeline & gate checklist
Timeline node = numbered 22px circle in verdict color; rail 1px border.default. Each entry: executor summary (body/secondary) → reviewer note (2px quote rule, muted, prefixed “reviewer:”) → Pi trace link (mono 11px, external ↗). A dashed node marks the in-progress iteration. Gate rows: glyph + mono check name + state; failed rows get a 6% red tint; pending is colorless. Gates run after reviewer approval — the summary line states x/n passed.

5 · Data table & live-update affordances
CSS grid rows, fixed 41px height, fixed column template — SSE patches change cell content in place, so nothing ever reflows or reorders while connected (re-sorting happens only on reconnect/refresh). On patch: row bg flashes liveFlash then eases out over 800ms; the last-event timestamp renders link-blue for 2 minutes. Relative timestamps re-render every 10s. Header + all data cells: mono 10.5–11.5px; entity names are the only sans cells.

6 · States & the read-only contract
loading
Skeleton rows at final row height (no jump on data arrival), pulsing at 1.6s. Footer shows the literal request: GET /api/snapshot …
empty
Dashed border, queued-gray glyph, one sentence saying what will appear and who puts it there. Failures-empty is the one celebratory state: ✓ nothing blocked.
disconnected
Red global banner + sidebar indicator flips to disconnected with the close timestamp. Data stays visible, labeled as a snapshot; simulation of freshness stops (timestamps keep aging honestly).
Read-only contract: the interface contains zero buttons. Interactions are navigation (rows, cards, breadcrumbs) and external links (Pi traces, repos, live sites — always suffixed ↗). Escalations are surfaced, never actioned here; the sidebar footer states the contract explicitly. Any future write surface is a different product.
