## Server additions — `dashboard/server/` (write endpoints on a **separate, writable** connection; all other endpoints stay read-only)

- `POST /api/engagements` `{ idea?, site_url?, customer_name? }` → 400 unless at least one of idea/site_url; calls the orchestrator's `createEngagement` (the same function `loopctl new` uses — import it, don't duplicate) with `TENWHY_REPO_BACKEND` from env; returns `{ id }` (201). This is the "loopctl new equivalent API" of P10.1; the daemon picks it up.
- `GET /api/engagements/:id` → the engagement + its loop runs, iterations, gate checks (subset of the snapshot filtered by engagement).
- `GET /api/engagements/:id/research` → `{ research: <RESEARCH.json>, comparison: {columns, rows} }` from the customer repo (404 until the research gate passed).
- `GET /preview/:id/*` → static files from `state/customers/<slug>/website/dist/` (404 until the website gate passed). Served with `X-Frame-Options: SAMEORIGIN` so the results page can iframe it.
- `POST /api/engagements/:id/approve` → **409** unless `engagements.status = awaiting_approval`; else insert `approvals` (`approve`), event `approval.submitted`, return `{ ok: true }`.
- `POST /api/engagements/:id/request-changes` `{ notes }` → 400 if `notes` empty; **409** unless `awaiting_approval`; insert `approvals` (`request_changes`, notes); event `approval.submitted`; `{ ok: true }`.
- SSE: `GET /api/events?engagement=<id>&since=…` filters patches to that engagement (reuse the P6 stream).

## Pages — `dashboard/web/src/customer/`

1. **Start** (`#/` on the customer entry): `Meet tenwhy` + one-line promise; mascot (black circle, two white rounded-bar eyes; float 4 s + blink 5 s keyframes); white rounded-24 input card with the two inputs, helper line, black `↑` circle submit; mono footer `research → review → build → launch · ~20 minutes · nothing published without your ok`. Submit → `POST /api/engagements` → navigate to loading.
2. **Loading** (`#/e/<id>`): mascot with spinning ring; cycling phase title/sub; 5-step checklist driven by **real events** over SSE (not timers):
   | step | done when |
   |---|---|
   | 1 reading your site / brief | first `loop_run.started` for `company-research` |
   | 2 researching the market | first `iteration.recorded` for `company-research` |
   | 3 planning | `gate.checked` for `company-research` with all passed (or `handoff`) |
   | 4 building your site | first `iteration.recorded` for `website` |
   | 5 final checks | `gate.checked` for `website` |
   Done = filled black `✓` circle; active = spinning border-top circle + "in progress"; upcoming at 45 % opacity; progress bar with sweep shimmer + `step n of 5`; copy `you can keep this page open — nothing is published without your ok`. `engagement.status = awaiting_approval` → auto-advance to results. `needs_human` → a calm "we've paused to check something — we'll pick this up" state (no button). Reload-safe: initial state comes from `GET /api/engagements/:id`, then SSE.
3. **Results** (`#/e/<id>/results`): pill segmented control with two tabs:
   - **Research**: plain-language cards from `/research`: *about your business* (`company.summary`), *what we learned* (✓ bullets from competitor summaries), *how your site will win* (numbered, from `enhancement_ideas`), competitor table (`name / pricing shown / what they do well / link`) + the comparison table (`{columns, rows}`, ✓/⚑ cells, shared renderer with the ops dashboard).
   - **Website design**: the drafted homepage in a neutral browser frame = `<iframe src="/preview/<id>/">` (site uses the customer's brand colours from `brand/tokens.json`, never tenwhy's); sidebar cards: page checklist (list of `dist/**/*.html` from the server) + "built from your research — nothing invented".
   - Both tabs share the actions: **Approve & launch** → `POST …/approve` → "launching…" state → on `engagement.complete` event show the `live_url` (from the event payload) as a link; **Request changes** → textarea + submit → `POST …/request-changes` → back to loading at step 4 with copy "rebuilding with your notes". Disable both while the request is in flight; show a 409 as "this project isn't waiting for approval right now".
   These are the **only** write actions in the front end besides creating the engagement.
