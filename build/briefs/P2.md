## P2.1 — `system/tools/scrape.py`

CLI: `scrape.py --url <url> --loop-run-id <id> [--db <path>] [--out-dir <dir>] [--allowlist host1,host2]`.

Behaviour:
1. **Allowlist** (optional): if given and the URL host is not in it → refuse.
2. **robots.txt** honoured via `urllib.robotparser` (user-agent `tenwhy-research/1.0`), cached per host under `<out-dir>/robots/<host>.txt`. Disallowed → refuse. Unreachable robots.txt → allow (standard behaviour) and note it in the output.
3. **Rate limit**: ≥ 2 s between requests to the same host, enforced across processes with a per-host lock/state file under `state/scrape/<host>.last` (sleep until allowed).
4. **Fetch** with Scrapling (`scrapling.fetchers.Fetcher.get`, `timeout=30`, `follow_redirects=True`, custom user-agent). Do not use the stealth/browser fetcher in v1.
5. Save raw HTML to `<out-dir>/<sha1(url)>.html` and an extraction JSON to `<out-dir>/<sha1(url)>.json` = `{url, final_url, http_status, title, text (visible text, whitespace-normalised, max 200 kB), links: [{href, text}], fetched_at}`. `content_path` = the JSON file.
6. Insert a `scrapes` row `(id, loop_run_id, url, http_status, content_path, created_at)`. Non-2xx responses still get a row with their status and content_path.
7. **Refusals** (allowlist/robots): insert a `scrapes` row with `http_status = NULL`, `content_path = NULL`, plus an `events` row `kind = "scrape_refused"`, `payload = {"url", "reason": "robots" | "allowlist"}`; print `{"url", "refused": true, "reason"}` and exit 3.
8. Success: print `{"url", "http_status", "content_path"}` to stdout, exit 0. Network/timeouts: `events` row `kind="scrape_error"` and exit 4.

Default `--out-dir`: `state/scrapes/<loop-run-id>/`.

Tests — `system/tools/test_scrape.py` (stdlib `unittest`, run with the venv python): start a local `http.server` on a random port in a temp dir serving `robots.txt` (`User-agent: *\nDisallow: /blocked/`), `/ok.html`, `/blocked/secret.html`, `/missing` (404). Use a temp DB migrated with `system/db/migrate.sh`. Assert:
- `/ok.html` → exit 0, `scrapes` row with `http_status = 200`, JSON file contains the page title and text;
- `/blocked/secret.html` → exit 3, `scrapes` row with `http_status IS NULL`, `events` row `scrape_refused` reason `robots`;
- `--allowlist example.com` against the local server → exit 3, reason `allowlist`;
- `/missing` → row with `http_status = 404`;
- two consecutive fetches of the same host take ≥ 2 s wall-clock.
Add to `make verify`. Also run one real fetch: `system/tools/.venv/bin/python system/tools/scrape.py --url https://example.com --loop-run-id smoke --db /tmp/tenwhy-smoke.db` (migrate that DB first) and paste the JSON output + `sqlite3 /tmp/tenwhy-smoke.db "select url,http_status from scrapes"`.

## P2.3 — Generic loop runner

`system/orchestrator/loop_runner.mjs` (library + CLI) implementing SOP §1 "Loop protocol":

```
runLoop({ db, loopName, engagementId, attempt, changeRequestId, adjustedInstructions,
          workdir, config /* loops.yaml */, adapter /* model adapter */, gateRunner })
```
1. Insert `loop_runs` (status `running`, `attempt`, `change_request_id`, `adjusted_instructions`, `started_at`); event `loop_run.started`.
2. For `n = 1..caps.iteration_cap` (4):
   - **Executor turn**: `adapter.run({ role:"executor", loopName, n, prompt, sessionId, workdir })` → returns `{ outputPath, traceRef }`. Prompt = loop's executor prompt + adjusted instructions + previous reviewer notes (if n>1).
   - **Reviewer turn**: `adapter.run({ role:"reviewer", ... })` → returns raw text. Parse the **last** JSON object in the text of shape `{"verdict": "...", "notes": "..."}`. If missing, unparsable, or `verdict` ∉ {`revise`,`approve`,`reject`,`escalate`} → coerce to `verdict="revise"`, `notes="FORMAT: reviewer output did not contain {verdict, notes} with a valid verdict; original: <first 500 chars>"`.
   - Insert `iterations` row (`n`, `executor_output_path`, `reviewer_verdict`, `reviewer_notes`, `pi_trace_ref` = executor trace); event `iteration.recorded` with payload `{n, verdict, executorTrace, reviewerTrace}`.
   - `approve` → break to gate. `escalate` → loop_run `needs_human`, event `loop_run.needs_human`, return. `reject` → loop_run `gate_failed` (fails upward; orchestrator decides retry), return. `revise` → continue.
3. Cap exhausted without `approve` → `gate_failed`.
4. **Gate**: `gateRunner({ loopName, workdir, db, loopRunId })` → `[{check_name, passed, detail}]`; insert `gate_checks` rows; status `gate_passed` iff all passed, else `gate_failed`; event `gate.checked` + `loop_run.finished` with `finished_at`.
5. Return `{ loopRunId, status, iterations, gateChecks }`.

Adapters:
- `system/orchestrator/adapters/pi.mjs` — real adapter: runs the loop's `run-pi.sh` with `PROVIDER/MODEL/thinking` from `loops.yaml` roles, `SESSION_ID = randomUUID()`, `SESSION_DIR = state/pi-sessions/<engagement>/<loop-run>`, sets `TENWHY_LOOP_RUN_ID`/`TENWHY_DB`, parses `--mode json` output, returns `traceRef = "pi://session/<SESSION_ID>"`. **Serialize Pi launches per provider with an in-process mutex** (environment.md risk note). Not exercised by tests (needs logins) — keep it thin.
- `system/orchestrator/adapters/fixture.mjs` — test double: takes a scripted list of responses per role and returns them in order (executor writes its text to a file in `workdir`; reviewer returns raw text). `traceRef = "fixture://<role>/<n>"`.

Tests — `system/orchestrator/test_loop_runner.mjs` (`node --test`, temp DB via `migrate.sh`, gateRunner fixture):
- A: reviewer `revise` then `approve`; gate all-pass → `loop_runs.status = gate_passed`, 2 `iterations`, `gate_checks` rows, events in order `loop_run.started, iteration.recorded ×2, gate.checked, loop_run.finished`.
- B: reviewer returns prose with no JSON → iteration 1 verdict `revise`, notes start with `FORMAT:`.
- C: four `revise` → 4 iterations, status `gate_failed`, no `gate_checks`.
- D: `escalate` on iteration 1 → status `needs_human`.
- E: `approve` but gate fixture fails one check → `gate_failed`, the failing `gate_checks` row has `passed = 0` and the right `check_name`.
Add to `make verify`.
