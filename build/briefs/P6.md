## Server — `dashboard/server/` (Node ≥ 20, `node:http`, `node:sqlite`, no framework)

- `server.mjs`: `npm run dashboard` serves `dashboard/web/dist/` (after `vite build`) and the API on `http://127.0.0.1:4310` (`PORT` env). In dev, `vite` proxies `/api` to it.
- **Read-only connection** for everything in this phase: `new DatabaseSync(TENWHY_DB, { readOnly: true })`. Write endpoints do not exist yet (Phase 7 adds two, on a separate connection).
- `GET /api/snapshot` → JSON:
  ```
  { serverTime, snapshotAt, lastEventId,
    engagements: [{ id, customer_name, idea, site_url, repo_url, status, created_at, updated_at,
                    live_url,                      // from the latest events.kind = engagement.complete payload, else null
                    kb_files: [{ path, updated }], // actual *.md files under the engagement's persisted repo dir (slug from the engagement.created event / P3-fix item 5 — never re-derived from customer_name); never hardcoded names
                    active_loop, last_event_at, last_note }],
      loop_runs: [{ id, engagement_id, loop_name, attempt, change_request_id, status, pi_trace_ref,
                    adjusted_instructions, started_at, finished_at,
                    iteration_count, last_verdict, last_note, last_event_at }],
      iterations: [{ id, loop_run_id, n, executor_output_path, executor_summary, reviewer_verdict, reviewer_notes, pi_trace_ref, created_at }],
      gate_checks: [{ id, loop_run_id, check_name, passed, detail, created_at }],
      scrapes:     [{ id, loop_run_id, url, http_status, created_at }],
      approvals:   [{ id, engagement_id, action, notes, created_at }],
      comparisons: { [loop_run_id]: { columns: [{ key, label }], rows: [{ cells: [{ value, state?, href? }] }] } } }
  ```
  `executor_summary` = first 240 chars of the executor output file (read from `executor_output_path`, or `""` if missing). `comparisons` is keyed by loop_run id and built **only for the latest `gate_passed` `company-research` run of each engagement** (the customer repo holds one `RESEARCH.json`, so earlier runs cannot be described reliably — the loop detail of a superseded run shows `comparison superseded by run_x`) from `research/RESEARCH.json` `product_matches`: columns `customer product · competitor · competitor product · price · source`; a cell is `state: "valid"` when the match has a numeric price **and** its `source_url` has a `scrapes` row with `http_status = 200` for that run, else `state: "flagged"`; `href` on the source cell. Timestamps are server values — never derived from the client clock.
- `GET /api/events?since=<lastEventId>` → SSE. Tail the `events` table by `id` (poll every 500 ms; `--offline`-safe). Each message:
  ```
  event: patch
  id: <events.id>
  data: { id, kind, engagement_id, loop_run_id, payload, created_at,
          entities: { engagements: [...], loop_runs: [...], iterations: [...], gate_checks: [...], scrapes: [...],
                      comparisons: { [loop_run_id]: {columns, rows} } /* present on gate.checked / loop_run.finished of a research run, so a finished comparison appears without reconnect */ } }
  ```
  `entities` holds the **re-read current rows** for every entity the event touched (by id), in the same shape as the snapshot, so the client patches in place. Heartbeat comment `: ping` every 15 s. Honour `Last-Event-ID` on reconnect.
- `seed.mjs <db>`: migrates and seeds a demo DB mirroring the mocks: `Cobalt Legal` (`eng_0141`, running, research iteration 2/4, attempt 0), `Meridian Dental` (`eng_0142`, needs_human, website 3/4, attempt 1, adjusted instructions, one failed gate check `lighthouse≥85` — deployment is not a loop gate, so `deploy_200` from the mock is not a valid check name), one `awaiting_approval` engagement with a research run that has `product_matches` (write a minimal customer repo under `state/customers/<slug>/research/RESEARCH.json` + `company/*.md` so `kb_files` and `comparisons` populate), one `complete` with `live_url`, one `queued`/`new`. `npm run dashboard:seed`.

## Web — `dashboard/web/` (Vite, vanilla ESM, no UI library)

- Fonts: `@fontsource-variable/geist` + `@fontsource-variable/geist-mono` (self-hosted; fall back to `system-ui` / `ui-monospace`). `font-variant-numeric: tabular-nums` wherever data appears.
- `src/status.js` — **the one shared status module**: reads `dashboard/design/tokens.json` (import) and exposes `statusOf(kind, value)` → `{ fg, bg, border, glyph, label }` for engagement/run/gate/verdict values using the alias table (`engagement.new → queued`, `engagement.complete → passed`, `run.gate_passed → passed`, `run.gate_failed → failed`, `gate.pending → queued`, `verdict.revise → running` with glyph `↺`, `verdict.escalate → needs_human`, `engagement.awaiting_approval → queued`). The mapping is **exhaustive** over every enum: engagement `new|running|needs_human|awaiting_approval|complete|failed`, run `queued|running|gate_passed|gate_failed|needs_human`, gate `pending|pass|fail`, verdict `revise|approve|reject|escalate`; an unknown value renders with the `queued` style, its raw label, and a single `console.warn` — a unit test asserts every enum value resolves and that an unknown value cannot introduce a colour outside `tokens.json`. Labels are the **verbatim** enum values, lowercase, mono. No other file may define a status colour.
- `src/store.js`: holds the snapshot; `applyPatch(event)` replaces rows by id **without re-sorting**; marks touched row ids for the flash; relative-time re-render every 10 s; "recent" (link-blue) last-event timestamps for 2 min. `src/sse.js`: EventSource with reconnect (retry n/5, backoff), states `live | reconnecting | disconnected` (with close timestamp); on reconnect, refetch snapshot and **only then** re-sort.
- Views (hash-routed `#/runs`, `#/runs/<eng>/<run>`, `#/failures`, `#/customers`), each with **loading** (skeleton rows at final 41 px height, footer `GET /api/snapshot …`), **empty** (dashed border, `○` glyph, one sentence; Failures-empty = `✓ nothing blocked`), and **disconnected** (red global banner outranking the amber needs_human banner; data stays, labelled `snapshot <time>`) states:
  1. **Runs** — CSS-grid table, fixed 41 px rows, fixed column template: engagement (name + mono id), status badge, active loop, iteration segments (4 × 14×4 px) + `n/4`, attempt dots (3 × 6 px, amber when attempt > 0) + `n/2`, last event (relative), last note. Row click → loop detail. Footer legend from the mock.
  2. **Loop detail** — breadcrumb `runs / eng_x / run_x`; header; pipeline strip `01 company-research → 02 website` with per-loop status, active highlighted; amber `orchestrator adjusted instructions` callout (mono, pre-wrap) when attempt > 0 or change_request_id set; left: iteration timeline (22 px numbered node in verdict colour, 1 px rail, executor summary → `reviewer:` quoted note → `pi://…` trace link `↗`, dashed node for in-progress iteration); right: gate checklist (`x/n passed`, failed rows 6 % red tint) + scrape provenance (status code coloured, URL, relative time); below, for research runs with a comparison: full-width comparison table (30 px header, 33 px rows, mono, `✓` valid / `⚑` flagged cells).
  3. **Failures** — cards, needs_human first, coloured left accent; rows: failed check (red chip), reviewer objection (quoted), orchestrator adjustment (mono; amber for needs_human). Card click → loop detail.
  4. **Customers** — 2-col grid of engagement cards: status dot + name + mono id + status; `kb_files` list (actual filenames + relative `updated`); external links `repo ↗`, `live ↗` (only when present).
- Sidebar: `tenwhy/` wordmark, connection card (green pulsing `live · SSE /api/events` / amber `reconnecting · retry n/5 in Ns` / red `disconnected` + close time), nav `▤ Runs (active count)`, `⚑ Failures (amber count)`, `▦ Customers`, footer `read-only console … snapshot <time> · v0.1.0`. **Zero buttons anywhere** — navigation and external links only.
- Live behaviour: patched rows flash `color.liveFlash` easing out over **800 ms** (the mocks/build prompt; the stale `1.5s` wording in `tokens.json` `rules.liveUpdate` was corrected); nothing reflows or reorders while connected.
- Design-source conflicts, resolved: **run rows are 41 px** (Specs/mock; `tokens.json` `space.tableRowHeight` corrected to 41) and have **no coloured left edge** (needs_human rows get the 4 %-alpha amber tint only); **Failure cards keep their coloured left accent**.
